Jenkins CI/CD pipeline — GitHub push to verified deployment

Every stage must pass before the next runs. Deploys use a Helm rolling update with automatic rollback.
1–2GitHub push → CheckoutWebhook / SCM poll triggers the job; image tag = build number + commit SHA
3–4Install & Buildnpm ci in node:22 container, HTML lint, build dist/ + version.json, archive artifact
5Test14 storefront tests (JUnit report) + AI analyzer unit tests
6Security checks(parallel) Gitleaks secrets · Trivy dependencies · Trivy IaC/K8s config
7–8Docker build → Image scanMulti-stage, non-root image; Trivy gate fails on fixable CRITICAL CVEs
9–10Push → DeployRegistry (local / ECR) → helm upgrade --install, maxUnavailable 0, auto-rollback on failure
11–12Health check → Success/health, pages and /version.json through the ingress; build marked successful
Continuous integrationDevSecOps gatesContinuous deliveryOperations
On failure: Helm rolls the release back automatically → Jenkins collects Kubernetes events, pod logs and Helm history → the AI incident analyzer classifies the failure, rates severity, and writes incident-report.md (archived with the build) with probable root cause, investigation and remediation steps.
